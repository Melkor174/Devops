# Этап 1. Ручной деплой на Linux-сервер

**Легенда.** Разработчики принесли приложение. Нужно поднять его на сервере так, как это делают в проде: без root-запуска, с автостартом, reverse-proxy и закрытыми портами.

**Цель:** `curl http://<IP-сервера>/health` отдаёт `{"db":"ok","redis":"ok"}`, и сервис переживает перезагрузку сервера.

## Задания

### 1.1 Зависимости
- Установите PostgreSQL, Redis, nginx, Python 3 + venv.
- Создайте в Postgres базу `notes` и пользователя `notes` с **нормальным паролем** (не `notes`).
- Postgres и Redis должны слушать **только localhost**. Проверьте командой `ss -tlnp`.

### 1.2 Пользователь и файлы
- Создайте системного пользователя `notes` (без shell, без домашней директории для логина).
- Приложение кладите в `/opt/notes`, виртуальное окружение внутри, владелец `notes`.
- Переменные окружения храните в `/etc/notes/app.env`, права `600`, владелец `root`. В коде и в Git паролей быть не должно.

### 1.3 systemd-сервис
- Напишите unit `/etc/systemd/system/notes.service`: запуск gunicorn от пользователя `notes`, `EnvironmentFile`, `Restart=on-failure`, запуск после `postgresql.service` и `redis-server.service`.
- Включите автозапуск (`enable`).

### 1.4 nginx
- Настройте reverse-proxy: порт 80 → `127.0.0.1:8000`, передавайте заголовки `Host` и `X-Forwarded-For`.
- Проверьте конфиг (`nginx -t`) до перезагрузки.

### 1.5 Безопасность по минимуму
- Файрвол (`ufw`): разрешены только 22 и 80 (и 443, если будете делать HTTPS).
- SSH: вход по ключу, `PasswordAuthentication no`, root-вход запрещён. **Сначала проверьте вход по ключу во втором окне терминала, иначе заблокируете себя.**
- По желанию: бесплатный сертификат Let's Encrypt (нужен домен).

### 1.6 Логи
- Найдите, где лежат логи приложения (`journalctl -u notes`), nginx (`/var/log/nginx/`) и Postgres.
- Настройте ограничение размера журнала systemd (чтобы логи не съели диск).

## Готово, если
- [ ] `curl http://<IP>/health` → 200, `curl -X POST -H 'Content-Type: application/json' -d '{"text":"hello"}' http://<IP>/api/notes` → 201.
- [ ] После `sudo reboot` всё поднимается само.
- [ ] `ss -tlnp` показывает наружу только 22 и 80.
- [ ] Процесс gunicorn работает не от root (`ps aux | grep gunicorn`).
- [ ] Вы можете объяснить, что делает каждая строка вашего unit-файла.

## Подсказки
- Сервис не стартует: `systemctl status notes`, затем `journalctl -u notes -n 50 --no-pager`.
- 502 от nginx значит, что приложение не отвечает на 8000: `ss -tlnp | grep 8000`, `/var/log/nginx/error.log`.
- Приложение ждёт БД до минуты и пишет об этом в лог, это нормально.

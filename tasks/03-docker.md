# Этап 3. Docker и docker-compose

**Легенда.** «На сервере руками» неудобно: каждый раз всё настраивать заново. Упакуйте проект так, чтобы он запускался одной командой на любой машине.

**Цель:** `docker compose up -d` поднимает весь стек: nginx, app, postgres, redis.

**Сначала поймите разницу:** образ (шаблон), контейнер (запущенный экземпляр), том/volume (данные вне контейнера), сеть (контейнеры видят друг друга по имени сервиса).

## Задания

### 3.1 Dockerfile для приложения
Создайте `app/Dockerfile`:
- Базовый образ `python:3.12-slim`.
- Сначала копируйте и ставьте `requirements.txt`, потом код (чтобы работал кэш слоёв, объясните себе почему).
- Запуск не от root (создайте пользователя).
- `CMD` с gunicorn (`-w 1 --threads 4 -b 0.0.0.0:8000 app:app`).
- Добавьте `.dockerignore` и `HEALTHCHECK` (дёргает `/health`).

### 3.2 docker-compose.yml
Сервисы: `app`, `db` (postgres:16), `redis` (redis:7), `nginx`.
- Конфигурация через `.env` файл (в Git его не коммитим, коммитим `.env.example`).
- Данные Postgres в named volume.
- `restart: unless-stopped` для всех.
- `healthcheck` для `db` (`pg_isready`) и `depends_on` с `condition: service_healthy`.
- Наружу публикуется **только порт 80 у nginx**. Postgres и Redis наружу не выставляем.
- nginx в контейнере проксирует на `app:8000` (конфиг монтируйте как файл).

### 3.3 Миграция с этапа 1
- Остановите и отключите сервисы из этапа 1 (`notes`, nginx на хосте), чтобы не конфликтовали порты.
- Поднимите стек. Проверьте `/health` и POST/GET заметок.

### 3.4 Эксперименты (обязательно, тут главное понимание)
1. Добавьте заметку, сделайте `docker compose down`, потом `up`. Заметка на месте? Теперь `docker compose down -v`. Что случилось и почему?
2. Поставьте неправильный `DB_PASSWORD` у `app`. Что видно в `docker compose ps` и `docker compose logs app`?
3. Убейте процесс внутри контейнера (`docker compose kill app`). Что делает `restart`?
4. Зайдите внутрь: `docker compose exec app sh`. Какой пользователь? Какие переменные окружения? Что видно по `docker stats`?
5. Ограничьте память `app` (`mem_limit: 200m`) и повторите «утечку» из этапа 2. Что произойдёт? Как увидеть, что контейнер убит по OOM (`docker inspect`)?
6. Сравните размер образа с `python:3.12` и `python:3.12-slim` (`docker images`).

### 3.5 Ответьте письменно в NOTES.md
- Чем контейнер отличается от виртуальной машины?
- Что такое слой образа и почему порядок строк в Dockerfile важен?
- Зачем нужен volume?
- Как контейнеры находят друг друга по имени?

## Готово, если
- [ ] Весь стек стартует с нуля одной командой на чистой машине (проверьте на втором сервере или после `docker system prune -a`).
- [ ] Данные БД переживают пересоздание контейнеров.
- [ ] Postgres и Redis недоступны снаружи (`nmap`/`ss`/попытка подключиться с другой машины).
- [ ] Вы можете объяснить каждую строку вашего compose-файла.

## Подсказки
- Логи: `docker compose logs -f --tail=100 app`.
- Пересборка после правок: `docker compose up -d --build`.
- Для nginx достаточно `location / { proxy_pass http://app:8000; ... }`.

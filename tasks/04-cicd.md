# Этап 4. CI/CD: автоматический деплой из Git

**Легенда.** Сейчас обновление = «зайти по SSH и руками пересобрать». Это медленно и ненадёжно. Нужно: пуш в `main` → тесты → сборка образа → деплой на сервер без ручных действий.

**Цель:** изменение в репозитории само появляется на сервере через пару минут.

## Задания

### 4.1 Репозиторий
- Создайте репозиторий на GitHub (или GitLab), положите проект из этапа 3.
- Добавьте `.gitignore`: `.env`, `venv/`, `__pycache__/`. **Проверьте историю: секретов в Git быть не должно.**

### 4.2 Pipeline: проверки
Workflow GitHub Actions `.github/workflows/ci.yml`, срабатывает на каждый push и pull request:
- Линтер Python (`flake8` или `ruff`) по `app/`.
- Проверка, что образ собирается (`docker build`).
- Дополнительно: `docker compose config` (валидность compose-файла) и `hadolint` для Dockerfile.

### 4.3 Pipeline: публикация образа
При пуше в `main`:
- Соберите образ и опубликуйте в **GitHub Container Registry** (`ghcr.io/<user>/notes`).
- Теги: `latest` **и** короткий хеш коммита (`sha-abc1234`). Объясните себе, почему деплоить `latest` плохо.

### 4.4 Pipeline: деплой
- Создайте на сервере отдельного пользователя `deploy` с SSH-ключом только для деплоя (не ваш личный ключ).
- Приватный ключ, адрес сервера и пользователь хранятся в **GitHub Secrets**, а не в коде.
- Job деплоя по SSH: заходит на сервер, подтягивает конкретный тег образа, выполняет `docker compose up -d`.
- Деплой происходит **только из `main`**, и только если предыдущие шаги прошли.

### 4.5 Проверка после деплоя и откат
- Последним шагом pipeline проверьте `curl -f http://<IP>/health`. Если не ответил — job падает (красный), а вы получаете сигнал.
- Сымитируйте плохой релиз: внесите ошибку, из-за которой приложение не стартует (например, неверный порт в `CMD`). Что показал pipeline? Что с сайтом?
- Сделайте откат: вручную на сервере выставите предыдущий тег (`sha-…`). Опишите шаги в `NOTES.md`.
- Усложнение: автоматический откат, если health-check после деплоя не прошёл.

## Готово, если
- [ ] Изменение текста на главной странице после `git push` появляется на сервере без вашего входа на него.
- [ ] Образы в registry имеют тег с хешем коммита.
- [ ] Секретов нет ни в репозитории, ни в логах pipeline.
- [ ] Вы умеете откатиться на предыдущий релиз за минуту.

## Подсказки
- Для SSH-деплоя удобны готовые actions вроде `appleboy/ssh-action` или обычный `ssh` в `run:` шаге с ключом из secrets.
- Логин в ghcr в Actions: `docker/login-action` с `GITHUB_TOKEN`. На сервере для `docker pull` понадобится токен с правом `read:packages` (или сделайте образ публичным).
- Ключ деплоя ограничьте: пользователь `deploy` только в группе `docker`, вход только по ключу.
